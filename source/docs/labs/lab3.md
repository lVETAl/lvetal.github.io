# Отчет по лабораторной работе № 3  
## CI/CD для статического сайта в SourceCraft  

### **Цель работы**  
Реализовать автоматическое развертывание статического сайта на базе MkDocs с использованием двух CI/CD-платформ: SourceCraft и GitHub Actions. Настроить работу с одним локальным репозиторием, синхронизируемым с двумя удалёнными (GitHub и SourceCraft). Получить две работающих версии сайта: на домене `*.sourcecraft.site` и на `*.github.io`.  

### **Среда разработки и архитектура**  
- **Язык и инструменты:** Python 3.11, MkDocs, Git, VS Code  
- **Удалённые репозитории:**  
  - `origin` – GitHub  
  - `sourcecraft` – SourceCraft (подключен по HTTPS с персональным токеном)  
- **CI/CD:**  
  - SourceCraft – автоматическая сборка через файл конфигурации 
  - GitHub Actions – workflow-файл `.github/workflows/deploy.yml`  
- **Структура проекта (общая для обоих удалённых репозиториев):**  
portfolio/
├── source/                 # исходные файлы MkDocs
│   ├── docs/               # Markdown-страницы
│   ├── skins/images/       # иконки и логотип
│   └── mkdocs.yml          # конфигурация сайта
├── docs/                   # сгенерированный сайт (публикуется)
├── .gitignore
├── .sourcecraft.yaml       # настройки CI/CD SourceCraft
└── .github/workflows/
    └── deploy.yml          # настройки GitHub Actions

### **Выполненные задания**  

#### **Настройка SourceCraft**  
1. Пройдена авторизация на платформе `sourcecraft.dev` с использованием аккаунта Яндекса.  
2. Создана публичная организация, а затем пустой репозиторий.  
3. Сгенерирован персональный токен.  
4. Локальный репозиторий настроен на работу с двумя удалёнными источниками.  
5. После отправки кода в SourceCraft платформа автоматически запустила сборку и опубликовала сайт.  

#### **Настройка GitHub Actions**  
1. В локальном репозитории создана папка `.github/workflows` и файл `deploy.yml` с описанием пайплайна.  
2. Workflow настроен на запуск при каждом пуше в ветку `main`. В нём последовательно выполняются: checkout кода, установка Python 3.11, установка MkDocs, сборка сайта командой `mkdocs build -f source/mkdocs.yml -d docs`. После сборки автоматически выполняется коммит и пуш обновлённой папки `docs` обратно в репозиторий от имени GitHub Actions.  
3. Для того чтобы workflow имел право пушить изменения, в настройках репозитория GitHub в разделе Actions → General включена опция Read and write permissions.  
4. После пуша в `origin/main` пайплайн отрабатывает, сайт обновляется  

#### **Синхронизация двух платформ**  
- Локальный репозиторий синхронизируется с обоими удалёнными серверами последовательным выполнением двух команд: `git push origin main` и `git push sourcecraft main`.  
- Кодовая база, включая CI/CD-конфигурации, полностью идентична в обоих репозиториях.  

### **Результаты**  
После завершения всех настроек получены четыре ссылки:  
- Статический сайт, развёрнутый на SourceCraft
- Репозиторий SourceCraft 
- Статический сайт, развёрнутый на GitHub Pages
- Репозиторий GitHub
